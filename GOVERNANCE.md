# Governance

`watchd` is currently an early-stage, maintainer-led open-source project.

## Roles

- **Contributors** participate through issues, design discussions, documentation, tests, and code.
- **Maintainers** review contributions, protect correctness and security boundaries, manage releases, and make final decisions when consensus is not reached.

The initial maintainer is [@usernamenenad](https://github.com/usernamenenad).

## Branch and release policy

`develop` is the default integration branch. `main` contains release-ready history. Both are protected; contributors work through reviewed pull requests and squash merges. The repository owner retains an administrative bypass for recovery, but normal project work follows the same checks as external contributions.

## Decisions

Routine changes are decided in the linked issue and pull request. Material changes to correctness guarantees, public APIs, security boundaries, source compatibility, or project governance require an issue describing alternatives and tradeoffs before implementation.

Maintainers prefer documented consensus. When reasonable contributors disagree, the maintainer records the decision and rationale in the issue so it can be revisited with new evidence.

## Becoming a maintainer

Maintainership is earned through sustained, constructive contributions and demonstrated care for the project's correctness, users, and community. As the contributor base grows, this document will be revised to define nomination and voting procedures.

## Project assets

Maintainers administer repositories, release credentials, package registries, domains, and communication channels on behalf of the project. Access should follow least privilege and be removed when no longer required.
